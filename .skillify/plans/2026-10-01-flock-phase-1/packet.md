## Invariants

- **I1:** Migrations are additive and idempotent; preserve source/set/item IDs, stars, active set, root, templates, onExisting, shallow/parallel/page/column/font/theme preferences and unknown workspace fields. Settings, credentials and worktrees are not reset. Ephemeral sessions, models, tokens and content are not persisted into workspace settings.
- **I2:** Rust derives/authorizes roots from configured workspace plus set item identity, verifies actual Git top-level/origin, and never trusts renderer absolute paths as mutation authority. Use typed DTOs, argument arrays, explicit namespaces, resolved object IDs, option termination and no shell command strings. Compare commands disable external diff/textconv execution. Existing user Git/SSH configuration remains otherwise compatible.
- **I3:** Protect .git case-insensitively, Git/common directories, nested repository metadata, symlinks, junctions, all reparse-point ancestors and Windows path aliases. Reject traversal, rooted/drive-relative/UNC child paths, ADS, reserved names and case collisions. Canonical string-prefix checks alone are insufficient. Filesystem writes must fail closed if safe handle-based containment cannot be established under ancestor replacement races.
- **I4:** Immutable revisions stay pinned to object IDs; mutable contents carry fingerprints. Serialize operations per repository/destination, revalidate before commit, and reject stale snapshots or concurrent external edits. Clone/fetch/pull/switch cannot race compare writes; refresh does not silently drop dirty editors.
- **I5:** Credentials are removed from args, URLs and stdout/stderr before events or storage; never record headers/tokens or raw file blob stdout as Activity text. - **I6:** No new write/delete is enabled without durable backup and successful restore proof. Git-object sides are never destinations. Undo checks current post-write fingerprint and never overwrites subsequent edits. Unsupported binary/encoding/link/gitlink cases are explicit, not silently coerced into text or recursively traversed.

## Comparison Contract (P3-P4)

Endpoints identify set item/local clone, ref kind/name and resolved SHA or working-tree generation. Repo URL or repoId alone is not identity: duplicate local folders must remain distinct. Keep the clone Ref type unchanged; introduce a separate compare endpoint union including workingTree.

Resolve branches/tags using complete refs/heads, refs/remotes and refs/tags namespaces; validate names using Git check-ref-format as appropriate. Accept existing 7-40 hex SHA input only after unique commit resolution using rev-parse --verify --end-of-options and commit peeling. Ambiguous, absent and noncommit objects are distinct outcomes. HEAD is a typed local convenience resolved before diffing; do not accept arbitrary revision expressions from the renderer. For a missing object/ref, coalesce one fetch attempt per local repo and compare request, using the validated namespace/SHA, then resolve again. No checkout, pull, prune, automatic unshallow or retry loop. Authentication/network errors stay distinguishable from missing refs. Never auto-clone an unavailable endpoint.

For revision inventories use ls-tree -r -z -l --full-tree; retrieve bytes lazily with show of backend-constructed resolvedOID:path or object ID. Same-repo change metadata uses diff --name-status -z and --numstat -z, with explicit no-ext-diff/no-textconv. Diff endpoint A against endpoint B directly, NOT A...B (the prototype's set help text uses merge-base semantics, unsuitable for endpoint content comparison). rev-list --left-right --count A...B and bounded side-exclusive commit lists describe ancestry only when both objects exist in the same history database. Unrelated histories and shallow limitations are labeled; cross-repo commit counts are unavailable unless common ancestry/object availability is actually proven.

Working-tree inventory starts with ls-files -z --cached --others --exclude-standard, overlays actual disk existence/content to account for staged/unstaged/deleted files, and excludes .git regardless of rules. Do not pretend HEAD->working-tree diff includes untracked contents. Nonignored untracked files are present; ignored/generated content is excluded by default. Inventory and content reads use the same root/link protections as mutations. Revision symlinks are blobs displayed as link targets; working-tree links/reparse points and submodule gitlinks are special rows, never followed. Submodule display shows recorded/local state without recursion or update.

Cross-repo compare is the union of root-relative paths from both inventories; compare contents/modes, not just size/date or differing object IDs (repositories may use different object formats). Same-repo status/numstat is an optimization, not the inventory source. For cross-repo text line counts, use Git diff --no-index --numstat on safely materialized temporary byte snapshots, accept exit 1 as differences, and exclude scratch files from worktrees; binary counts are unavailable, never zero. Renames remain explicit per-path presence/copy semantics; no implicit delete of the old path.

Folders are virtual aggregates, not Git objects or empty tracked directories. Orphan folders aggregate one-sided descendants; mixed folders aggregate all children. Filters retain ancestors of visible children; totals clearly distinguish full inventory from filtered view. Missing-side content is empty for text diff, not an invented file. Revision modification dates are unavailable unless explicitly obtained from history, not the prototype's fabricated timestamps. For working trees show actual safe-read metadata; modes, sizes and binary flags are preserved.

Whitespace/EOL ignores affect presentation/classification, not saved/copied bytes. Whole-file copies are byte-exact. Hunk copy uses current Monaco line mappings against the latest raw models; disable when diff is pending/stale, binary/unsupported, or ignored differences make mapping ambiguous. Insertions/deletions and no-final-newline/CRLF cases require tests. Folder copy means recursive source-present regular files under the selected prefix, NOT mirror/sync: skip special rows, never remove destination-only children, and preview each conflict. Copy of an absent source does not delete an orphan; deletion is not a Phase 1 action. Hunk removal inside a file remains available with undo.

## Mutation And Recovery Contract (P5-P7)

Recommend both: Monaco's bounded in-memory undo for unsaved buffer/hunk edits plus durable per-operation backups and a bounded session mutation undo index. Existing architecture persists only settings and reclone folder backups; an in-memory stack alone cannot recover a saved file after a crash. Do not scatter .bak files into compared worktrees.

Store backup bytes, originally-absent tombstones, fingerprints and operation manifests in the private Tauri app-data area, using opaque operation IDs; never store credentials. Persist the backup/manifest and verify readability/hash before target commit. Keep recoverable pending manifests across restart and expose recovery; do not claim the editor undo stack survives restart. Keep the last 50 mutation operations in session undo; retained backup data has a visible size/age list and explicit user-confirmed purge, no automatic deletion of unacknowledged recovery records. Backups may contain sensitive source and consume disk; use user-private storage and no network/export. If space is insufficient, abort before mutation. Exact quota/automatic retention is deferred; no unbounded silent cleanup policy.

Use unique create-new sibling temporary files, flush them, and a tested Windows atomic replace/create primitive through a narrowly scoped Windows dependency if required. Hold/revalidate safe filesystem handles so a concurrent junction substitution cannot redirect commits. No delete-then-rename workaround. Preserve supported encoding/BOM/EOL and relevant attributes; reject unsupported encodings, binary editing and locked/read-only targets. A rename API is not presumed to guarantee replacement/durability on Windows. Hard links must not allow an operation to alter external aliases; reject unsafe targets or prove replacement avoids modifying shared bytes.

For one file: backup failure, conflict, temp write failure or replace failure leaves original unchanged; report errors, clean owned temp files only, retain manifest/backups for uncertain commit outcomes. Validate resulting hash after commit. Folder operations are atomic PER FILE, not across a directory: preflight/preview all entries, journal completed entries, stop on failure, report partial completion and offer guarded undo. Do not automatically roll back over externally edited files. Undo an originally absent creation only if it still matches Flock's bytes; all other restores require the same containment, backup, atomicity and conflict checks.

Protected existing clone behavior: retain skip/fetch/reclone and fast-forward-only pull/switch semantics, but authorize all destinations through the same root rules. For reclone allocate a collision-free adjacent backup, verify moved folder, journal location and retain it on clone failure. Never recursively delete a partially cloned folder as recovery; report the backup location and restore only when doing so cannot overwrite intervening work. Existing out-of-root historical destinations are not silently moved/deleted; show blocked safety result until user chooses a valid root.

User owns scope, dependency acceptance, destructive decisions and final acceptance; orchestrator/integration owner advances the gates.

## Risks And Stop Conditions

| Risk | Likelihood / Impact | Mitigation / Owner |
| --- | --- | --- |
| Junction/path substitution or metadata write | Medium / critical data loss | P3/P5 fail-closed handle-based authorization; worker fixtures, reviewer security gate |
